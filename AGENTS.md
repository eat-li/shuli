# AGENTS.md

Agent-facing conventions for this repo (`teacher-assistant`). Generated by the
`setup-matt-pocock-skills` skill — edit the files under `docs/agents/` directly,
then update the summaries below if they drift.

## Agent skills

### Issue tracker

Issues and specs live as markdown files under `.scratch/<feature-slug>/` in this
repo (local-markdown tracker; no external tracker or CLI required). See
`docs/agents/issue-tracker.md`.

### Triage labels

The five canonical triage roles keep their default label strings: `needs-triage`,
`needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`, recorded as a
`Status:` line in each issue file. See `docs/agents/triage-labels.md`.

### Domain docs

single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root. See
`docs/agents/domain.md`.

Use the glossary's vocabulary in issues, specs, code comments and UI copy — the
terms are opinionated on purpose (e.g. 知识点 ≠ 关键词, 成绩记录 ≠ 测评成绩,
作业分类 ≠ 知识点分类). Each entry lists its `_Avoid_` synonyms; don't drift to them.

Existing ADRs:

- `docs/adr/0001-guest-token-isolation.md` — why guest and admin tokens go
  through different middlewares instead of one auth chain.
- `docs/adr/0002-readonly-site-is-a-separate-surface.md` — why `/readonly` owns
  its own layout and token file instead of reusing the admin shell.
- `docs/adr/0003-guest-code-lives-in-settings.md` — why the parent-portal access
  code lives in the `settings` table (not only `GUEST_CODE`) and how code
  rotation/disable invalidates issued guest tokens immediately.
- `docs/adr/0004-readonly-shares-admin-visual-language.md` — why `/readonly` now
  mirrors the admin's light "modern dashboard" theme and no longer follows the
  system dark mode.
